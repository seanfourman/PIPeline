# Projects

The evidence for rules 26 and 27 in `../10-cv-best-practices.md`.

## What to take from it

- Projects prove what the jobs don't, above all early in a career.
- Show a project like a job: what it is, the result, the technology, and a link to see it.
- One deep, real project beats several tutorial copies.

## When to include them

- **IBM:** with little work history, add a section for relevant class projects, side work or competitions. Source: [IBM](https://www.ibm.com/careers/blog/eight-common-resume-writing-mistakes-that-keep-you-from-getting-your-dream-job).
- **The Tech Interview Handbook:** at least two projects. Source: [Tech Interview Handbook](https://www.techinterviewhandbook.org/resume/).
- **Google's recruiters:** applicants for technical roles can legitimately have many relevant projects, and that alone may take a CV onto a second page. Source: [Inc.](https://www.inc.com/bill-murphy-jr/google-recruiters-say-these-5-resume-tips-including-x-y-z-formula-will-improve-your-odds-of-getting-hired-at-google.html).
- **An IBM recruiter:** "Projects, research, anything you've done – make sure you take credit for it all so we can realize your best work!" Source: [IBM](https://www.ibm.com/careers/blog/make-your-resume-stand-out-from-the-pile).
- The template marks the section optional; it is dropped when the posting doesn't need it.

## How to show them

- **Link the work.** The Tech Interview Handbook links the project name to GitHub or wherever a hiring manager can see it. Google's recruiters put a GitHub link at the top for technical roles. Sources: [Tech Interview Handbook](https://www.techinterviewhandbook.org/resume/), [Inc.](https://www.inc.com/bill-murphy-jr/google-recruiters-say-these-5-resume-tips-including-x-y-z-formula-will-improve-your-odds-of-getting-hired-at-google.html).
- **Role and reach.** Describe the candidate's role and the project's reach, such as how many others use it (Tech Interview Handbook). Name the programming languages used for each project (Google). Sources: as above.
- **Depth.** Gergely Orosz looks for strong projects: a README, tests, open source. Source: [Orosz](https://dev.to/gergelyorosz/six-principles-your-resume-should-follow-so-recruiters-will-read-it-3a0o).
- **The template's shape.** `\cvrole{\cvlink{url}{Project} - [one-line description]}{}`, then a bullet with the measured result and a bullet with the technical detail.

## What doesn't count for much

- A tutorial copy (a to-do list, a weather app, a course's capstone built by thousands) shows that a course was followed, not what the candidate can do. This follows the guides' emphasis on reach, depth and real results; no study measures it.
